# Excerpts · 当前设计规范 (beta.10)

**定位：Obsidian 原生视觉与行为 × flomo 式轻量记录 × Apple HIG 的内容优先、渐进披露原则。**

设计以实际产品为准，不保留早期 Collection / Entry / Extra 独立数据模型和多级管理界面。

## 优先级

1. **内容优先**：正文最醒目；日期、标签和按钮低对比、低密度。不要因为操作图标遮挡正文。
2. **减少选择**：首页只有快速记录、搜索、标签筛选和时间线。不需要珍藏状态、随机按钮、重复菜单或手动性能参数。
3. **渐进披露**：标签建议仅在展开编辑时出现；搜索输入初始折叠；已有 H2 分组通过胶囊展开，不额外设置“添加内容”菜单。
4. **主题一致**：字体、背景、描边、焦点、交互色继承 Obsidian 的 CSS tokens。所有样式限制在 `.excerpts-root`，不影响宿主。
5. **原生数据**：每张卡片对应一个普通 `.md` 文件，采用 `MarkdownRenderer` 渲染；保留正文、图片和音视频的 Obsidian 原始语义。
6. **可恢复**：保存失败保留输入，不能覆盖源文件。文件改动后由 Vault 事件刷新，不进行额外后台轮询。

## 页面结构

- 顶部：精简标题“摘录”
- 记录区：两行起始高度的文本域、按需展开的标签建议、一个保存按钮
- 时间线：标题“最近摘录”、数量、搜索和标签筛选入口
- 卡片：正文 → 标签 → H2 分组胶囊和展开内容 → 日期与一个编辑入口

删除操作只应发生在用户明确意图下；本阶段不提供卡片内独立的删除动作。

## 布局与触控约束

- 单栏布局，边距和卡片间距使用少量统一的空间 tokens；不堆叠多层边框、色块和阴影。
- 操作按钮集中在卡片底部，不与正文或媒体重叠。适配窄分栏与 320/390px 移动宽度。
- 触控输入和图标目标至少 44px；文字输入在移动端避免触发浏览器缩放。
- 组件焦点、禁用态、展开态、空状态和错误反馈清楚可见，避免额外冗余文案。
- Markdown 富文本必须限制溢出，图片、视频、表格和代码块不可撑破卡片宽度。

## 验收边界

通过 JS 模拟测试仅证明功能与基础 DOM 行为；仍须在真实 Obsidian 浅色/深色、第三方主题、桌面/移动设备下检查标题、首屏密度、卡片边距、输入框状态、H2 分组、标签建议和媒体。

已确定的下一项交互债务：当前卡片编辑仍会打开原生 Markdown 文件；若改为卡片原位编辑，应单独落实并测试取消、焦点和未保存草稿行为，不能把跳转编辑描述为原位编辑。
